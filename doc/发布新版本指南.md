# 发布新版本指南

Norn 通过 [GitHub Releases](https://github.com/duyl328/norn/releases) 分发安装包，并通过
Tauri Updater 提供自动更新。正式发布统一由 `.github/workflows/release.yml` 构建，
本地发布仅作为 CI 无法使用时的兜底方案。

## 版本号规范

版本号采用语义化版本 `MAJOR.MINOR.PATCH`：

| 变更类型                               | 版本调整 | 示例              |
| -------------------------------------- | -------- | ----------------- |
| 不兼容的行为、配置或数据格式变更       | `MAJOR`  | `1.4.2` → `2.0.0` |
| 向后兼容的新功能或明显能力增强         | `MINOR`  | `1.4.2` → `1.5.0` |
| 向后兼容的缺陷修复、性能或小幅体验改进 | `PATCH`  | `1.4.2` → `1.4.3` |

- 仅测试、文档或 CI 调整通常不单独发布，随下一次产品版本发布。
- 同一版本号不得重复发布，版本号必须单调递增。
- 当前正式流程只接受 `vX.Y.Z` 标签，不支持 `alpha`、`beta` 或 `rc` 预发布标签。
- 无法判断时，以对用户兼容性的影响为准，而不是提交数量或代码规模。

## 变更日志规范

所有用户可感知的变更都先写入根目录 `CHANGELOG.md` 的 `[Unreleased]`。准备发版时，
将本次内容整理为以下格式：

```markdown
## [X.Y.Z] - YYYY-MM-DD

### 新增

- 增加……

### 改进

- 优化……

### 修复

- 修复……

### 测试与工程

- 完善……
```

编写要求：

- 只保留实际存在的分类，不创建空分类。
- 按“新增、改进、修复、测试与工程、升级说明”的顺序组织。
- 使用用户能理解的结果描述，不直接粘贴提交记录、Issue 标题或内部实现细节。
- 破坏性变更、数据迁移、配置变化和已知限制必须单独写入“升级说明”。
- 不允许 `TODO`、`TBD`、“待补充”或“暂无”等占位内容。
- GitHub Release 正文和自动更新提示均从该版本章节自动生成，不再单独维护。

## 正式发布流程

### 1. 确认发布范围

1. 确认 `main` 已包含计划发布的变更，并且 CI 全部通过。
2. 检查 `[Unreleased]`，补齐遗漏的用户可见变更。
3. 根据上面的版本号规范确定 `X.Y.Z`。
4. 将 `[Unreleased]` 内容整理为 `## [X.Y.Z] - YYYY-MM-DD`，并保留一个新的
   `[Unreleased]` 章节供后续开发使用。

### 2. 同步版本号

以下四个文件必须使用同一个 `X.Y.Z`：

- `package.json`
- `src-tauri/tauri.conf.json`
- `src-tauri/Cargo.toml`
- `src-tauri/Cargo.lock` 中 `norn` 包的版本

本地执行 `pnpm tauri build` 会在非 CI 环境自动递增 patch 版本，并在 Cargo 构建时更新
锁文件。需要发布 `MINOR` 或 `MAJOR` 时，应手动同步四处版本号。

### 3. 执行发布前检查

```bash
node scripts/check-release-version.mjs vX.Y.Z
node scripts/release-notes.mjs vX.Y.Z
pnpm ci:full
```

至少还要确认：

- Windows 原生 P0 E2E 在 GitHub Actions 中通过。
- 当前版本涉及的平台专项测试已通过；无法验证的平台已记录为已知风险。
- `git status` 只包含本次发版相关改动。
- 签名公钥、更新地址和 GitHub Secrets 没有被意外修改。

### 4. 提交并创建标签

发布提交遵循仓库 Angular Commit Message 规范：

```bash
git add CHANGELOG.md package.json src-tauri/tauri.conf.json src-tauri/Cargo.toml src-tauri/Cargo.lock
git commit -m "chore(release): 发布 X.Y.Z"
git push origin main
git tag -a vX.Y.Z -m "Norn vX.Y.Z"
git push origin vX.Y.Z
```

必须先推送发布提交，再推送标签。标签只能指向已经通过 CI 的发布提交；创建或推送错误标签后，
不要复用该标签发布另一份代码。

### 5. 验证发布结果

推送标签后，GitHub Actions 会先执行以下门禁，再构建 macOS Apple Silicon 和 Windows x64：

- 标签格式为 `vX.Y.Z`。
- 四处项目版本与标签一致。
- `CHANGELOG.md` 存在对应版本章节且没有占位内容。
- 更新签名私钥已配置。

工作流成功后检查：

1. GitHub Release 标题、正文与 `CHANGELOG.md` 一致。
2. macOS、Windows 安装包、更新包、签名和 `latest.json` 均已上传。
3. `latest.json` 的 `version`、`notes`、平台下载地址和签名正确。
4. 从上一正式版执行一次“检查更新”，确认能发现、下载并安装新版本。
5. 安装包可以在目标平台冷启动并完成一次核心冒烟流程。

任何一项失败都视为发布未完成。优先修复后发布更高版本，不覆盖已有正式版本。

## 本地兜底发布

仅在 GitHub Actions 无法恢复且确实需要发布时使用。发布机器必须已通过 `gh auth login`，
并持有与客户端公钥配对的 `~/.tauri/norn-updater.key`。

```bash
TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/norn-updater.key)" \
TAURI_SIGNING_PRIVATE_KEY_PASSWORD="" \
pnpm tauri build

node scripts/check-release-version.mjs vX.Y.Z
node scripts/release-notes.mjs vX.Y.Z
pnpm release
```

`pnpm release` 默认读取 `CHANGELOG.md` 生成 GitHub Release 正文和 `latest.json.notes`。
`RELEASE_NOTES="..." pnpm release` 只用于 Changelog 文件暂时无法读取的紧急恢复，发布后必须把
最终说明补回 `CHANGELOG.md`。

当前本地兜底脚本只发布 macOS Apple Silicon 产物。需要 Windows 或其他架构时，应优先恢复
GitHub Actions，不要将不完整平台产物当作常规正式发布。

## 签名与自动更新

- 客户端读取 `https://github.com/duyl328/norn/releases/latest/download/latest.json`。
- 更新包必须使用 `TAURI_SIGNING_PRIVATE_KEY` 签名，客户端使用
  `src-tauri/tauri.conf.json` 中的公钥验签。
- 当前公钥 keyID 为 `452E55902840D5AE`。私钥只保存在 GitHub Secret 和受控发版机器中，
  不得提交到仓库或输出到日志。
- 私钥丢失后生成新密钥会使已安装版本无法自动升级，应尽最大可能从备份恢复原私钥。
- macOS 当前使用 ad-hoc 签名，首次安装仍可能出现 Gatekeeper 提示；自动更新不受此提示影响。

首次配置 GitHub Secret：

```bash
gh secret set TAURI_SIGNING_PRIVATE_KEY --repo duyl328/norn < ~/.tauri/norn-updater.key
```

只有在原私钥确认无法恢复时才能生成新密钥：

```bash
node node_modules/@tauri-apps/cli/tauri.js signer generate --ci -p "" -w ~/.tauri/norn-updater.key -f
cat ~/.tauri/norn-updater.key.pub
```

生成后必须同步 `tauri.conf.json` 的 `plugins.updater.pubkey`、GitHub Secret 和受控备份，
并明确告知旧版本用户需要重新下载安装。

## 发布失败处理

- **校验失败：** 修正版本号或 Changelog，重新提交后创建新标签。
- **构建失败：** 不创建手工资产占位；修复工作流或代码后重新发布更高版本。
- **部分平台上传失败：** 保留日志和产物，修复后重新运行失败任务；发布页未完整前不要对外公告。
- **Release 已公开但不可用：** 在发布页标记问题并尽快发布修复版本，禁止静默替换相同版本资产。
- **自动更新验签失败：** 立即停止发布，核对私钥与 `tauri.conf.json` 公钥，不得绕过验签。
