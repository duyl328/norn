# 下一轮自动化测试 TODO

## 1. 目标

下一轮测试优先保证 Norn 作为文本编辑器的基础可靠性，其次补齐真实 Git、桌面生命周期和高频工作台交互。

核心原则：

- 任何外部文件变化都不能静默覆盖用户尚未保存的内容。
- 打开、编辑、保存、关闭任一阶段发生删除、修改、重命名、替换或权限变化时，界面不能崩溃、卡死或进入错误的“已保存”状态。
- 操作失败后，编辑器内存内容、磁盘内容、Tab 状态和错误提示必须保持一致。
- 浏览器 mock E2E 用于精确制造竞态；真实 Tauri E2E 用于证明 IPC、文件系统、watcher 和 Git CLI 的完整链路。
- 真实文件和 Git 测试只操作独立临时目录、临时仓库和本地 bare remote，不依赖公网或用户个人配置。

## 2. 测试分层

每条用例按风险放到合适层级，不把所有情况都堆进慢速原生 E2E。

| 层级                       | 主要职责                                                | 建议命令               |
| -------------------------- | ------------------------------------------------------- | ---------------------- |
| TypeScript 单元/组件测试   | 状态机、竞态顺序、对话框分支、旧请求失效                | `pnpm test`            |
| Playwright + Tauri mock    | 完整 UI 操作和可控的 IPC 成功/失败/延迟顺序             | `pnpm test:e2e`        |
| Rust 文件系统/Git 集成测试 | 真实读写、原子写、mtime、编码、权限和 Git 结果          | `pnpm test:rust`       |
| Windows 原生 Tauri E2E     | 真实窗口、IPC、watcher、文件系统、Git CLI、托盘和单实例 | `pnpm test:e2e:native` |

用例标记：

- `P0`：数据安全和发布门禁，下一轮必须完成。
- `P1`：高频功能和平台稳定性，P0 稳定后完成。
- `P2`：压力、长尾平台差异和 nightly 场景。

## 8. 统一验收标准

每条文件相关 E2E 至少验证适用项：

- [ ] 编辑器内存内容。
- [ ] 磁盘字节内容和文件是否存在。
- [ ] 文档 path、name、size、mtime、encoding、BOM 和换行符。
- [ ] `content` 与 `savedContent` 的关系以及 Tab 脏标记。
- [ ] 活动 Tab、后台 Tab 和工作区没有被旧异步结果覆盖。
- [ ] 保存、错误、冲突、loading 状态最终复位。
- [ ] 用户未保存内容不会因重载、关闭、重命名、删除或失败重试而丢失。
- [ ] 成功操作不会被自己的 watcher 事件误判为外部冲突。
- [ ] 错误提示明确，用户可以重试、另存为、采用磁盘版本或保留编辑器版本。
- [ ] 无崩溃、死锁、无限等待、重复对话框或半初始化 Tab。
